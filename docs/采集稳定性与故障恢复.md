# 采集稳定性与故障恢复

## 采集范围与请求量

- 默认仍每10分钟同步。高频管理采集包括未结束、最近30天结束、仍有未解除风险的冲刺；可额外指定冲刺编号。
- 已保存的历史快照不再自动代表永久监控。人工完成或忽略提醒不等于远端风险解除，仍未解除的风险会继续核验。
- 历史冲刺的需求关联缓存到专属数据库，最长24小时；冲刺状态或日期等属性改变时立即重新读取。缓存只保存关联编号，不保存需求正文。
- 用例列表有最新状态、版本和修改时间字段时，可复用创建人、创建日期元数据，最长1小时；评审状态、变更标记等可变字段仍使用本轮响应。缺少可靠字段时重新读取详情。
- 历史缓存参与日期兜底且无法确认关联仍有效时，保留已有风险并等待核验，不能据此自动解除风险。读取失败、请求超限、权限不足也不能视为对象被删除。
- 每轮管理采集默认最多1500次远端请求；达到预算后保存缓存与续采位置，后续轮次轮转核验。未完整读取的范围标为待核验，不提交残缺列表作为完整事实。
- 连续3次连接失败后停止本轮管理请求；跨轮退避从2分钟逐步增加，最长1小时。手动完整刷新可主动重试，但仍遵循单轮互斥、请求预算和连续失败保护。

可在本机`.env`配置（下次重新创建工作台容器时生效）：

```dotenv
WORKBENCH_ZENTAO_REQUEST_BUDGET=1500
WORKBENCH_ZENTAO_TRACKED_EXECUTIONS=
```

`WORKBENCH_ZENTAO_TRACKED_EXECUTIONS`填写英文逗号分隔的正整数编号；留空使用自动范围。缓存、续采位置、连接退避按禅道地址与账号隔离，重启后继续有效。

需要强制重新读取历史关联与创建人元数据时，可在无其他采集执行的情况下请求：

```sh
curl --noproxy '*' -X POST http://127.0.0.1:8787/api/sync \
  -H 'Content-Type: application/json' \
  -d '{"source":"zentao","fullRefresh":true}'
```

其他采集尚未结束时返回409，不会静默将“完整刷新”合并到原有普通采集。单轮预算不足时需后续轮次继续核验，不能把一次响应理解为全库已核验。

每轮同步记录的`zentaoCollection`保存请求数、缓存命中数、监控范围、延后数量、连续连接失败次数、耗时及历史关联最早核验时间；同样写入服务端结构化日志。以上统计不含个人待办接口与登录请求，不代表Docker后台连接数。

## 数据库中断

- 启动时连接不可用，进程保持运行并返回503；按1、2、4、8、16、30秒的间隔重试，最长间隔30秒。SQL结构等非连接错误仍立即报错，避免无限掩盖迁移错误。
- 连接池、借出的事务连接、同步锁和实时监听连接都有错误保护。连接失效后销毁，不把回滚失败当作原始失败原因。
- 同步锁连接丢失时停止后续采集，避免在锁已失效时继续写入。已有提交记录保留，失败事务回滚。
- 运行中的数据库连接错误返回503和`Retry-After: 5`，连接恢复后后续请求可以重新连接。页面原有数据保留行为不变。

## Docker容器代理绕过

单纯减少采集请求不能保证修复Docker后台的资源泄漏；需要验证禅道请求不再经过存在积压问题的代理转发路径。

```sh
# 只预览变更
node scripts/docker-proxy-bypass.mjs --host=你的禅道域名
# 备份原配置并写入容器代理绕过设置，不重启Docker
node scripts/docker-proxy-bypass.mjs --host=你的禅道域名 --apply
```

脚本仅调整Docker容器代理，保留原HTTP/HTTPS代理地址与原有例外，并追加指定域名；不修改macOS系统代理或Docker Desktop自身的代理模式。遇到PAC或无法确认的配置会停止，不猜测替换。完整原配置备份保存在`.runtime/docker-proxy-backups/`，由Git和Docker构建上下文共同忽略。

Docker运行期间可能重新保存设置。重启前核对设置文件或Docker的容器代理设置，确认指定域名仍在绕过列表。重启Docker会中断其他运行容器，应安排维护窗口。本轮配置文件写入不代表运行时已经生效。

## 发布与验证

1. 维护窗口先重启Docker Desktop释放已经积压的连接，再核对容器代理绕过配置。
2. 经使用者决定构建时，执行`docker compose up -d --build workbench`；新增缓存表由迁移18自动建立，不清除业务记录。
3. 检查`http://127.0.0.1:8787/api/health`返回200，再检查同步记录及代理日志，确认禅道请求实际绕过代理。
4. 持续观察Docker后台文件描述符是否仍单向增长。单元测试与构建通过不能替代这项部署后观察。

普通验证使用`npm test`和`npm run build`；`npm run test:integration:local`会创建随机隔离测试库，额外覆盖缓存、迁移、真实数据库连接中断以及启动时数据库不可用仍返回503。不要在业务数据库中运行故障注入测试。
