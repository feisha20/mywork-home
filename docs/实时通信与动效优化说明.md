# 实时通信与动效优化说明

## 交付范围

本次实现《架构与工程改进方案》的专项二主干：SSE 实时状态与变更推送、断线轮询兜底、常驻 SVG 流光连续动画和布局测量合帧。沿用原有待办通知偏好、权限申请、首次基线与多窗口通知去重；用户未开启通知时不申请权限。

可选的 Web Push 未纳入本次交付。关闭全部工作台标签页后仍停止提醒，不新增 VAPID 密钥、浏览器推送订阅端点或第三方推送依赖。

## 服务端事件链路

`GET /api/events` 返回 `text/event-stream; charset=utf-8`，禁用缓存和代理缓冲，每 25 秒发送 `: heartbeat` 注释。连接携带 `retry: 3000`，交由原生 EventSource 自动重连。

| 事件 | 数据 | 用途 |
| --- | --- | --- |
| `sync:progress` | `harness`、`modelRuntime` | 同步阶段、渠道、扫描数、已成功处理批次、新增/更新数、当前模型展示信息 |
| `model:failover` | `from`、`to` 模型 ID，加模型运行状态和 `harness` | 请求连接失败后备用模型开始接管时即时更新 |
| `model:changed` | 模型运行状态和 `harness` | 调用开始、结束及设置更新 |
| `tasks:created` | `tasks` 摘要数组，仅含 ID、来源、编号、脱敏标题 | 提交后新增的非私人禅道和计划待办 |
| `workbench:changed` | `dataVersion` | 提示各标签页按需补读工作台及当日视图 |

数据库迁移 15 在任务、日报、周月报、禅道管理状态和同步运行记录上安装通知触发器，使用 PostgreSQL `LISTEN/NOTIFY`。通知在事务提交后才投递，因此回滚不产生提醒，也能覆盖计划调度、MCP、其他数据库连接及服务实例的写入。数据库通知本身只包含事件种类或新增记录 ID，不含业务正文、密钥和来源证据。

每个应用实例共用一个专属 LISTEN 连接，连接池需为普通查询保留连接。服务端将 60 毫秒内的数据库变更合并，再查询版本、同步状态或新增待办摘要；空闲心跳不查询数据库。模型接管直接订阅现有路由器，事件中不传模型连接地址或密钥。模型运行状态属于接收请求的本服务进程，未额外实现跨实例共享模型调用状态。

断开的客户端清理心跳；背压客户端断开后通过快照恢复，避免无限缓冲。数据库监听断开时结束对应 SSE，触发浏览器重连与轮询降级。应用在 Fastify `preClose` 阶段结束长连接并释放 LISTEN，避免关停等待 SSE 永不结束。

## 前端刷新与通知

- 每个工作台页面只建立一条 EventSource。连接成功时停止周期轮询；同步及模型状态直接更新组件，数据变更在 80 毫秒内合并为一次快照刷新。
- 首次连接和每次重连均补读快照。事件流不承担持久历史重放；断线期间的任务以数据库快照补齐，提醒继续使用已有去重规则。
- 断线、不支持 EventSource 或建立连接失败时，恢复每 30 秒刷新。重复的连接错误不会将低频兜底变成每次重连都发起请求。
- 快照请求串行执行；请求进行中又收到变更时排队补读，避免并发请求堆积。请求前的旧模型状态不能覆盖其间收到的新状态。
- 设置页、日报弹窗模型状态复用该连接；断线时才使用 30 秒兜底。后台且未启用通知时暂停快照刷新，返回页面后补读；启用通知时允许后台刷新并沿用系统通知逻辑。
- 计划生成的新待办也会触发“芯片 → 待办”流光。首次加载不回放旧任务；后台、减少动态效果和已有归档动效规则继续生效。
- 空闲期间仍会在北京时间跨日时刷新日期与当日视图。

## 动效与性能边界

采集连线及芯片圆角外圈使用 `pathLength="1000"` 和连续线性 `chip-flow` 关键帧。采集连线通过 `--flow-duration`、`--flow-color` 调整状态：空闲 16 秒、工作 4 秒、当前渠道 2 秒；芯片外圈保持工作时 6 秒循环，空闲停止。保留隐藏页面暂停动画、未连接渠道静态展示以及 `prefers-reduced-motion` 规则。

`ResizeObserver` 与窗口 resize 共用 `requestAnimationFrame` 测量调度器，同帧多次变化只测量一次。渠道状态更新只改变 CSS 变量和样式，不因同步状态变化重新读取布局；组件卸载取消待执行帧。

原实现已使用 CSS 动画，本次主要移除芯片外圈的阶梯帧率、统一路径尺度和速度、减少布局测量。SVG `stroke-dashoffset` 在部分浏览器仍会触发绘制，不能将纯 CSS 等同于完全运行在 GPU 合成线程。本次未进行浏览器性能录制，不宣称实测 CPU 或帧率收益。

## 验证与使用

```bash
# 普通 TypeScript 测试；不启动浏览器
npm test -- src server shared
# 运维脚本使用 Node 原生测试器单独运行
node --test scripts/data-maintenance.test.mjs
npm run build
# 真实 Harness + 本机模拟 HTTP 模型，不发送真实工作资料
npm run test:harness
# 仅运行本次 SSE 集成测试，自动创建与清理随机隔离库和角色
npm run test:integration:local -- -t SSE
# 全量数据库回归
npm run test:integration:local
```

集成测试使用现有 `postgres18` 容器，不构建镜像、不重启业务容器，不读取业务数据库。允许通过已有的 `WORKBENCH_TEST_POSTGRES_CONTAINER`、`WORKBENCH_TEST_POSTGRES_PORT` 覆盖测试 PostgreSQL 地址；两个集成测试入口都支持将额外参数传给 Vitest。

本次验证中，SSE 专项 5 项、运维脚本 10 项、Harness 5 项测试通过，普通 TypeScript 测试亦通过。全量入口尚有两个既有问题：直接 `npm test` 会让 Vitest 误收集使用 `node:test` 的运维脚本；全量数据库回归的一项禅道上线风险测试期望“已取得上线节点”，实际为“计划或关联范围已调整”，已在未修改的 HEAD 临时副本中复现。本次不扩展修复禅道业务逻辑。

本机静态构建不等于部署。Docker 业务服务尚未重建或重启，迁移 15 尚未应用到业务库。需要部署时，在项目目录执行 `docker compose up -d --build workbench`；服务启动后自动执行迁移，无需安装新依赖。未启动浏览器，页面动画观感、实际多标签页表现和 Mac 系统通知仍需浏览器验收。
