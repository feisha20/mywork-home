# 禅道测试经理待办

自动抽取的关注事项直接进入现有待办面板，可完成或忽略，不增加独立管理入口和待办筛选栏。

## 连接与字段设置

启用禅道渠道后，管理采集默认随同步开启；可在设置中单独暂停，个人 Bug 和任务继续采集。管理待办及对应日报摘要使用本地规则与模板。

配置需求自定义字段的实际接口路径，例如 `customFields.plannedReleaseAt`、`customFields.actualReleaseAt`，数组结构也支持 `customFields.0.value`。点击“核对需求接口字段”可查看一个可见需求返回的字段标识及是否填写，再填写路径并保存。核对操作不保存草稿，不返回需求正文或字段值。留空时仅识别准确的中文字段名／标签“计划上线时间”“实际上线时间”，不猜测英文字段。

监控账号可见项目的未结束冲刺和最近30天关闭的冲刺；已发现事项所在冲刺持续跟踪。读取项目、冲刺、需求、用例、测试单和 Bug，补齐有效冲刺的需求关联后选择兜底冲刺。

## 日期依据

需求计划／实际上线时间分别优先使用需求字段。只有明确为空、空白或禅道零日期才兜底。多个有效关联冲刺按计划结束时间最晚选择，相同时间取较大编号；两个兜底日期都取同一个冲刺的 `end`／`realEnd`。所选冲刺尚无实际完成时间时继续判断上线风险。[禅道执行字段说明](https://www.zentao.net/book/api/2164.html)

使用北京时间；临期默认提前3个自然日，只有日期时截止当天结束后才算延期。双方都包含时间时按具体时间判断是否延期上线。非法日期、未来实际时间或重复字段标签提示核对；字段未返回、权限不足、缺页或读取失败会标记待更新，不能当作未填写。日期依据变化保留原值与变更记录。

取得实际上线节点后自动收起当前上线风险；实际晚于计划只计入“延期上线”历史。需求未关闭时仍会产生收尾事项。

## 关注事项与人工处理

自动抽取需求临期／延期、日期待补充／核对、评审积压、需求变更待确认、临期严重缺陷、需求关闭收尾、测试单关闭收尾及冲刺延期。用例覆盖缺口不生成待办，仅保留覆盖率统计。评审阈值默认3天，可调整。测试单原始状态 `done` 表示已关闭，兼容 `closed`，均不生成关闭收尾提醒；`wait`、`doing`、`blocked` 才属于未关闭。

需求上线风险按地址、账号、规则和需求编号去重。需求关闭、测试单关闭和严重缺陷按冲刺汇总。同一问题持续存在时更新事实与等级，汇总对象增加也不会重新打开已完成／已忽略记录。完整读取确认解除后复发，创建新一轮记录。

- **完成**：表示已处理关注事项，进入工作日志。
- **忽略**：移出待办，保留处理记录，不计入工作成果。
- **恢复**：风险仍存在时可恢复为待办。
- **自动收起**：完整同步确认条件解除后收起，说明取得上线节点、计划调整或移出范围等原因，不视为人工完成。

## 概览与数据完整性

后台管理快照记录上线进度、冲刺推定上线数量、延期需求、延期上线历史、需求关闭率、用例覆盖率、待评审数量、严重缺陷和未关闭测试单。红色表示延期、关闭残留或临期严重缺陷，黄色表示上线准备／用例准备问题，绿色表示数据齐全且没有规则异常；数据缺口单独标记并保留已确认风险。

每日保存最近一次完整快照；不完整采集不写当日指标，保留已知统计，无法判断的指标保留为空。成员按用例创建人统计关联数、冲刺内新增、最近7天新增／修改和待评审数；没有设计计划时不计算完成率。

各冲刺独立提交采集结果；行锁和事务保护人工状态，同步不会覆盖人工选择。快照、每日指标、风险轮次、日期依据及处理状态保存在 PostgreSQL，数据库迁移在服务启动时执行。

## 接口与验证

| 接口 | 用途 |
| --- | --- |
| `GET /api/tasks/management` | 按 `state=pending/completed/ignored/resolved` 分页；支持 `projectId`、`executionId`、`severity`、`offset`，默认50条，最多100条 |
| `PATCH /api/tasks/:id` | 管理事项支持 `{action: "complete"/"ignore"/"restore"}`，兼容 `{completed: boolean}` |
| `GET /api/zentao/management` | 当前连接的健康概览、成员统计、每日快照及数据完整性 |
| `POST /api/settings/inspect-zentao-fields` | 用草稿连接核对需求字段，复用相同身份的已保存密码，不保存草稿 |

运行 `npm test`、`npm run test:integration:local` 和 `npm run build`。规则测试覆盖字段优先级、多冲刺选择、日期边界、数据缺口及去重；隔离数据库测试覆盖重复同步、跨重启处理状态、并发人工操作、风险复发、日期历史和冲刺独立提交。测试不启动浏览器。
