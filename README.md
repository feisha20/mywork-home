# 我的工作台

个人工作台：通过禅道 V2 接口采集个人待办，读取本机 Codex、Claude Code、WorkBuddy、Zcode 和 Gemini CLI 会话，并使用 DeepSeek Harness 与火山 Coding Plan 整理会话工作事项。会话工作记录按来源消息的原始日期（北京时间）直接进入日志，不需要人工完成；手工待办和禅道事项完成后进入日志。日期显示在“工作日志”标题后面，主面板显示今日日志。点击标题右侧的日历图标并选择日期，即可在弹窗查看该日记录；弹窗支持关闭按钮、Esc 和点击遮罩关闭。

点击工作日志右上角的“生成日报”，即可总结当前日期的日志。生成时先按项目、交付成果或主要工作目标归类，再为每类撰写一句简洁总结；同一项目的功能开发、修复、验证和优化合并汇报，通常整理为3～6点，每点建议30～60个字符、最多80个字符，英文每个字母、空格与标点也计入长度，省略测试数量、技术参数及构建部署等过程细节。超长摘要仅对不合格项重新概括，保留已合格的其他条目，完成校验后再保存；不会机械截断内容。独立项目较多时可增加条目。日报只读取日志简介、项目名和状态，不读取会话证据，也不向模型发送本机完整项目路径。

生成的日报与整理标记按日期保存在数据库，刷新页面和重启服务后仍保留。已有日报时入口变为“查看日报”，再次打开直接读取保存内容，不自动重新生成。日志卡片显示“已整理”或“待整理”；新增日志或已整理日志的简介、状态发生变化后，点击“补充整理”即可只处理这些待整理记录，相关进展并入原分类，未涉及的条目保留。保存失败时原日报与整理标记保留，保存版本检查避免并发覆盖。点击“一键复制”可复制包含日期和编号条目的纯文本。历史日志也支持以上操作。日报生成独立于后台同步，不修改原日志、任务状态和同步进度。

## 计划任务

头像菜单中的“计划任务”可新建、编辑、暂停、恢复或删除周期事项。支持每天、工作日（周一至周五）、每周、每月、每季度和每年，可指定生成时间、开始及结束日期，并选择是否为个人事项。提供日报、周报、月报、季度报告、提交自己的 OKR 和审核部门 OKR 的常用模板，点击后可调整日期。

时间统一按北京时间；每季度可以选择季度内第几个月，月日期超出该月天数时取月末，例如每月 31 日在 2 月落到 28 或 29 日。工作日规则不排除法定节假日。新建、修改或恢复计划从当前时间起安排，不追溯生成之前的事项；暂停期间不补发。修改和删除计划只影响未来生成，已有待办与日志保留。

服务运行时每 30 秒检查到期计划；服务停机期间错过的事项在重启后分批补齐。每期独立生成一条标有“计划任务”和计划时间的待办，同一计划同一时间只生成一次，完成或删除该待办不会重复生成。计划及发生记录持久化在 PostgreSQL 中，生成待办和推进计划游标在同一事务完成，支持多实例并发。生成事项可置顶、完成、删除和调整个人分类，完成后沿用现有工作日志流程。此功能生成待办提醒，报告提交和 OKR 审核仍由用户完成。

## 工作与个人事项

待办、今日日志和历史日志卡片均提供“标为个人”开关，已标记时显示“个人事项”，再次点击即可改回工作事项；新建手工待办也可以直接选择“个人”。个人事项保留原记录、来源和完成状态，但不会进入工作日报、周报、月报的正文及统计。

会话抽取同时让 AI 判断是否为私人事务：依据事项的实际用途区分职业工作与生活、家庭、兴趣等个人安排，工作与私人内容分别提取，无法确定时先按工作处理。AI 判定的个人事项显示“AI”提示，允许随时修改。分类来源与完成状态独立保存，人工改正的分类不会被后续同步覆盖，AI 仍可更新事项进展。已有历史记录默认按工作处理，可以逐项改正，升级不会重新发送历史会话给模型。

将已整理的记录改为个人后，关联日报会立即移除含此记录的摘要；若摘要混合了工作内容，其中的工作记录重新变为待整理，可通过“补充整理”重新归纳。改回工作后同样可以补充整理。已有自动周月报在下次读取时按新分类更新；人工编辑的报告保留正文并提示复核，需自行检查并保存，或点击“重新整理”生成排除个人事项的新稿。报告生成期间的分类变更也会阻止旧素材覆盖保存结果。

## 日历日志与周月报

在“工作台设置 → 自动化”中开启“待办通知”并允许浏览器通知后，禅道同步或计划任务生成的新待办会触发 Mac 系统通知，点击通知可返回工作台。只提醒进入待办的事项，首次加载历史待办、普通手工新增、已完成记录和重复刷新均不提醒；同批次合并提醒，同一浏览器的多个窗口共享通知去重记录。通知开关立即生效，保存在当前浏览器，无需点击保存。

需要支持 Notification、Service Worker 的浏览器，以及 HTTPS 或本机 `localhost` / `127.0.0.1` 地址。开启后工作台切到后台仍继续检查新待办，空闲时约每 30 秒检查一次；浏览器限制后台运行或 Mac 休眠时可能延迟。关闭工作台后停止接收，重新打开时不补发历史通知。此功能不包含页面关闭后的 Web Push。若授权后仍未看到通知，请检查 Mac 系统设置中的通知权限及专注模式。

点击工作日志标题右侧的日历，选择日期即可查看当天的记录和日报。首页只获取当日记录、手工待办和日期索引，按日期查看日志时分页读取，来源正文在展开卡片时独立加载。

头像菜单打开“个人空间”后可切换周报和月报，保留原版的最近八周、六个月选择及三段报告展示。整理方式使用原版逻辑：按日期提取已保存日报的条目并去重，保留其主题；没有日报摘要时才以完成事项补充成果。推进中事项和下阶段计划沿用原版生成方式，不预先生成或改写日报，也不额外将日志逐条拼入成果。

周月报的读取、重新整理和编辑保存已接入数据库。服务器保存成功才显示已保存，刷新页面和重启服务后可再次读取；过期版本返回冲突提示。原版浏览器 localStorage 报告在打开对应周期时迁移，服务器已有报告优先，旧缓存仍保留。自动任务保留人工保存的正文。上一轮优化生成的自动稿会恢复为原版整理方式，人工保存的报告保持原文。

设置可启用自动日报、每周固定日期与时间的周报、月末固定时间的月报，均按北京时间执行。调度记录和检查点写入数据库，重启后补齐遗漏的触发，失败按次数递增间隔重试（5～60 分钟）；周月报直接汇总已有日报与事项后保存。停用计划暂停对应任务领取，数据库租约用于恢复异常中断的任务。

来源正文被编辑或 Gemini 可见历史撤回时，原引用保留为历史参考并标记失效，相关事项提示“来源已变更”，自动判断的完成状态撤销并重新核对。慢模型的过期结果不能写入。稳定消息标识的正文变动及通用来源带原消息标识的正文新版本可重新抽取；完整有效的 Gemini 快照负责撤回传播，半行或损坏快照不会撤回已有记录。无法确定原消息身份的通用记录不猜测替代关系。

## Docker Compose 部署（推荐）

需要 Docker Desktop 与 Docker Compose v2。本项目复用现有 PostgreSQL，不启动另一套数据库。本机当前 PostgreSQL 位于 `localhost:5432`；容器通过 `host.docker.internal:5432` 访问。

首次初始化：

```bash
bash scripts/setup.sh
```

按隐藏输入提示填写管理员连接。管理员连接示例格式：`postgresql://postgres:经过URL编码的管理员密码@host.docker.internal:5432/postgres`。初始化只创建工作台数据库 `mywork_home` 和用户 `mywork_home_app`，随机生成专属密码，写入权限为 `600` 的 `.env`；后续正常服务使用专属账号。模型密钥可在启动后的设置页填写，初始化不再要求输入。重新初始化沿用已有密码和密钥，不自动重置已有用户。

```bash
bash scripts/start.sh
# 或在初始化后运行：
docker compose up -d --build workbench
```

打开 [本机工作台](http://127.0.0.1:8787)。容器启动后自动扫描最近 7 天的消息，然后每 10 分钟增量同步。初次扫描可能需要多轮模型请求；页面核心区域会显示进度、新增数量和需要重试的记录。

Compose 只读挂载以下目录，路径可在 `.env` 修改：

| 配置 | 默认目录 |
|---|---|
| `CODEX_SESSIONS_DIR` | `~/.codex/sessions` |
| `CODEX_ARCHIVE_DIR` | `~/.codex/archived_sessions` |
| `CLAUDE_PROJECTS_DIR` | `~/.claude/projects` |
| `WORKBUDDY_PROJECTS_DIR` | `~/.workbuddy/projects` |
| `ZCODE_DB_DIR` | `~/.zcode/cli/db` |
| `GEMINI_SESSIONS_DIR` | `~/.gemini/tmp` |

挂载目录必须存在；首次运行可创建缺失的空目录。Docker Desktop 需要能够读取这些目录。容器保留会话中原始项目路径，无需挂载项目源码。Harness 运行数据保存在独立卷 `harness-runtime`。

Zcode 使用正式会话数据库 `db.sqlite`，整个数据库目录以只读方式挂载，包含 `db.sqlite-wal` 与 `db.sqlite-shm`，可读取正在使用中的会话。仅提取可见的用户文字和已结束的助手回复，过滤工具结果、推理、系统合成提醒及压缩摘要。按消息及文字片段的更新时间增量读取，以稳定消息标识去重；流式回复结束后再抽取，原始项目路径、父会话及消息时间均保留。目录可通过 `ZCODE_DB_DIR` 自定义，无需读取 Zcode 认证配置。

Gemini CLI 只扫描 `tmp/<项目>/chats` 下的正式 `.jsonl` 或旧版 `.json` 会话，通过 `.project_root` 保留本机项目路径。按[官方会话格式](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/services/chatRecordingTypes.ts)恢复完整历史快照、正文补丁和回退，过滤工具结果、内部思考、系统提示与附件，优先保留用户实际显示的正文。未变化的文件不重读；变化后重建可见历史，按会话、消息及正文版本去重，消息日期仍使用原始时间。嵌套子会话关联父会话。只读挂载会话临时目录，不读取 Gemini 登录凭证或设置，路径可通过 `GEMINI_SESSIONS_DIR` 自定义。

### 运行管理

```bash
docker compose ps
docker compose logs --tail=100 workbench
docker compose restart workbench
docker compose stop workbench
docker compose down
```

升级代码后运行 `docker compose up -d --build workbench`；数据库迁移在启动时自动执行，使用数据库锁避免并发迁移。停止服务会关闭模型子进程并保存同步状态，下次启动从数据库进度恢复。`docker compose down` 保留运行卷和外部 PostgreSQL 数据。

构建默认使用 Docker 缓存。Node 基础镜像固定到已核对的官方镜像摘要，避免同名标签更新导致依赖层重新安装；升级基础镜像时更新 `Dockerfile` 中的 `NODE_BASE_IMAGE` 默认值。依赖只执行一次 `npm ci`，构建阶段与生产依赖阶段共用安装结果，随后离线移除开发依赖；运行镜像只复制生产依赖和构建产物。BuildKit 的 `mywork-home-npm` 下载缓存独立保留，不再清空 npm 缓存；首次填充该缓存仍需下载，后续依赖层重建可以复用已下载包。仅修改业务代码时无需重新安装依赖。

`WORKBENCH_PORT` 修改宿主机访问端口，默认 `8787`。若数据库部署在其他位置，修改 `WORKBENCH_DB_HOST` 和 `WORKBENCH_DB_PORT`；本机直接运行使用 `DATABASE_URL`。默认端口只对本机开放。

### 数据备份与恢复

当前本机 PostgreSQL 容器名是 `postgres18`，其他环境请替换成实际名称。备份覆盖工作台 schema，包括任务、来源证据、游标、抽取批次、日报、周月报、自动报告执行记录及检查点与迁移版本。

```bash
mkdir -p .runtime/backups
docker exec postgres18 pg_dump -U postgres -d mywork_home -Fc --schema=workbench > .runtime/backups/workbench.dump
```

恢复会覆盖该工作台 schema，操作前保留当前备份并停止工作台：

```bash
docker compose stop workbench
docker exec -i postgres18 pg_restore -U postgres -d mywork_home --clean --if-exists --exit-on-error < .runtime/backups/workbench.dump
docker compose up -d workbench
```

同时妥善保留本机 `.env` 和运行目录中的 `settings/workbench.json`，它们不包含在镜像或数据库备份中。设置文件包含模型密钥、禅道连接凭据和采集路径，仅服务端运行用户可读写；本机开发位于 `.runtime/settings/workbench.json`，Docker 部署位于 `harness-runtime` 卷的 `/app/.runtime/settings/workbench.json`。恢复到新 PostgreSQL 时先运行初始化程序创建同名专属用户及数据库，再恢复工作台备份。

## 本机开发

需要 Node.js 24 与 npm。

```bash
npm ci
# 若尚未初始化，设置临时 WORKBENCH_ADMIN_DATABASE_URL 后：
npm run db:init
npm run dev:server
```

另一个终端运行：

```bash
npm run dev
```

前端使用 `http://127.0.0.1:5173`，API 代理到 `http://127.0.0.1:8787`。生产构建与本机运行：

```bash
npm run build
npm start
```

浏览器旧记录属于原站点地址。首次升级时，通过原来的 `http://127.0.0.1:5173` 打开一次页面，将原 localStorage 中的手工事项迁移到数据库；示例不导入。迁移保留原 ID、创建时间和完成日期，重复导入不会覆盖服务器状态，旧缓存仍保留。

## 工作台设置

点击右上角“我”头像打开设置，分为“模型配置”“采集源”和“自动化”三个页面。桌面端采用侧边导航，小屏改为顶部导航；修改后点击“保存设置”，关闭有未保存修改的窗口时会提示保留或放弃草稿。“记录读取方式”采用工作台主题下拉菜单，支持方向键、回车确认和 Esc 收起，空间不足时向上展开。

- **模型配置**：最多保存 10 个模型，每个模型分别填写配置名称、基础地址（Base URL）、模型名称和 API Key，可单独测试、启停、移除及调整优先顺序。页面顶部显示已保存配置当前默认的模型与最近实际使用的模型；列表标记首选、备用和正在编辑，点击列表只编辑配置，“设为首选”及顺序调整需保存后生效。移除操作位于详情底部，确认后先修改草稿，保存后生效。兼容 OpenAI Chat Completions，工作台自动补齐 `/chat/completions`。旧版单模型及密钥自动迁移。密钥不回传明文；留空保留、输入新值替换，勾选“清除已保存密钥”可删除；更换基础地址后需重新填写密钥，草稿不会存入浏览器缓存。
- **模型自动切换**：默认开启，按优先级使用已启用且有密钥的模型。可将公司模型排第一，在家无法访问时自动尝试个人模型；如果两个模型在家都可访问，仍使用优先级较高的模型，可手动调整顺序。连接、上游请求失败或超时后切换备用模型，故障模型冷却 1 分钟再按优先级尝试恢复。多模型时，前面的模型每次最多等待 30 秒，并为后续模型预留时间；整个请求受原批次超时限制。输出格式或证据校验失败继续原模型的纠错流程。关闭自动切换后只使用优先级最高的可用配置。备用模型会收到同一请求的资料，请仅启用允许处理这些资料的服务。
- **自动采集**：设置启停与 1～1440 分钟的间隔。保存后立即重新计算下次同步时间；关闭自动采集后仍可手动同步。正在运行的一轮采集或日报生成固定使用启动时的模型配置，下一轮开始使用新配置。
- **渠道顺序**：拖动列表或使用上下箭头调整顺序，首页 Logo、详情列表和实际扫描顺序均遵循设置。首页保留最多五个入口，超过五个时前四个独立展示，其余进入“更多”。设置页提供当前顺序预览。
- **渠道配置**：可修改名称、上传不超过 256 KB 的 PNG/JPEG/WebP Logo，或恢复默认图标；图标保存在设置中。停用渠道会暂停该来源的扫描与失败消息重试，已有任务、工作日志和游标保留。
- **禅道设置**：选择采集源中的“禅道”，填写禅道首页地址、账号和密码，测试连接后启用并保存。使用 `/api.php/v2/users/login` 登录及 `/api.php/v2/my/work/bug`、`/api.php/v2/my/work/task` 分页读取个人工作列表；已采集事项退出个人列表时，通过 `/api.php/v2/bugs/:id`、`/api.php/v2/tasks/:id` 补查详情，无需本机采集目录。密码只在服务端保存，接口仅返回是否已配置；留空保留、更换地址或账号时重填，停用后可清除。连接测试检查 Bug 和任务读取权限并显示待处理数量，不保存草稿。
- **路径设置**：“扫描”检查各采集器的常用目录、首次环境配置和已保存路径。目录卡片显示本机路径、读取状态及会话文件数量；打开渠道或修改路径时自动核对，也可点击“重新核对”。“手动输入”每行填写一个本机目录，支持 `~/`，保存和重新打开设置后仍显示本机路径。内部读取路径由服务端自动转换，新增未授权目录会提示先在部署配置中授权访问。Codex 会话和归档目录可同时保留。检查只遍历目录项并核对访问权限，不读取认证文件或会话正文；计数限制为 3000 个文件、20000 个目录项或 1.5 秒，达到限制时显示“至少”或“待核对”。保存后才开始使用选择的路径。
- **新增渠道**：默认“自动识别”，按文件内容识别已有工具的记录，并尝试通用 JSON / JSONL，不受渠道名称限制。扫描结果需勾选属于该渠道的目录，也可以手动填写新工具的本机目录；不会将所有扫描结果直接纳入采集。已有工具保持专用读取器，自定义兼容渠道可以在自动识别和通用读取之间切换，也可暂不采集。
- **通用字段**：支持 JSONL 逐行消息、JSON 消息列表、多会话导出和常见消息字典。自动匹配常用角色、正文、时间、会话与项目字段；不匹配时选择“通用 JSON / JSONL”，配置消息列表、角色、正文、时间、会话标识、消息标识和项目目录的字段名。嵌套字段使用点分隔，例如 `body.text`；字段只读取自身属性，不执行表达式。消息时间支持 ISO 时间、秒或毫秒时间戳，缺失有效时间的记录不使用文件时间补造日期。角色支持 `user` / `human`、`assistant` / `ai` / `model` 等常见值。
- **检测记录**：手动检查当前草稿，显示识别格式、检查与可解析文件数量、具体问题，以及最多三条脱敏正文预览。只在本机读取样本，不调用模型、不保存草稿；目录可读取不等于格式已兼容。预览最多检查八个文件，JSON 快照最大 8 MB，JSONL 采用有界增量读取。跳过认证、配置、缓存和工具/推理正文；通用目录遍历不跟随软链接，目录范围过大时需缩小范围。
- **兼容边界**：可识别的 JSON / JSONL 统一转换为会话、角色、时间、正文和项目；每个自定义渠道保留独立来源、游标与去重标识。字段配置变化会重新读取文件，正文版本改变会产生可再次抽取的消息。自动识别数据库仅支持已接入的 Zcode 表结构；其他 SQLite、私有二进制、加密或在线 API 来源仍需导出为兼容 JSON / JSONL 或增加读取器，不能仅改 Logo 完成接入。

首次启动时将原环境变量作为默认值导入 `.runtime/settings/workbench.json`，随后以界面保存的设置为准，不需要改环境变量或重启服务。设置目录权限为 `700`，文件权限为 `600`，保存使用临时文件原子替换；版本校验避免两个页面互相覆盖。密钥仅在服务端使用，设置接口不返回密钥且禁止缓存。模型、路径、Logo 和排序保存在运行目录，业务记录仍保存在数据库。

Docker 部署只能读取容器已挂载的目录。设置页依据当前容器的实际挂载信息显示对应的 Mac 目录，不根据 `/records` 名称猜测路径，也不需要挂载 Docker socket。内置读取目录分别为 `/records/codex/sessions`、`/records/codex/archived_sessions`、`/records/claude/projects`、`/records/workbuddy/projects`、`/records/zcode/db` 和 `/records/gemini/tmp`，这些地址只在服务端内部使用。新增 Mac 目录时，先在 Compose 中增加只读挂载并重建容器，再在设置中填写本机路径；`.env` 的路径变量仍用于宿主机挂载位置。当前识别 Docker Desktop 共享盘的挂载元数据；其他部署若未提供可识别的本机路径，会显示无法识别并暂停该目录的手动编辑，已有采集目录保留，仍可修改其他设置。

## 模型与同步规则

- DeepSeek Harness、SDK、模型适配器固定为 `0.2.0-rc.2`。
- 火山 **Coding Plan** 地址为 `https://ark.cn-beijing.volces.com/api/coding/v3`，协议为 OpenAI Chat Completions，套餐模型名称为 `glm-5.3-flash`。
- 使用工作台独立 Harness home，不改写本机 `~/.dsh` 配置；关闭 Shell、额外会话上传及插件清单上传，只向模型发送脱敏后的会话文字。
- 不读取认证文件，过滤工具输出和内部推理；在本机数据库写入前隐藏密钥、口令、授权信息。模型子进程仅接收模型密钥，不接收数据库凭证。
- 会话结束不代表工作完成。模型必须引用真实消息证据，没有明确完成证据时保留为待办。卡片可展开查看来源。
- 自动抽取的标题使用日报式工作项简介，通常20～40字，最多60字，突出工作对象、行动和目标或结果。文件名、代码参数及实现细节保留在来源证据，不堆进标题；不编造收益或完成状态。
- Codex、Claude Code、WorkBuddy、Zcode、Gemini CLI 工作记录直接归档；归档时间单独保存，不会把进行中的工作伪装成已完成。
- 禅道和自定义（手动添加）待办支持多个置顶：卡片右上角可置顶或取消置顶，置顶项统一排在前面，各组按创建时间倒序；状态保存在数据库中，刷新和禅道同步后保留。
- 只有手工待办和禅道任务提供完成、恢复待办按钮，芯片右侧统计为今日日志数量。
- 首次回溯起点写入数据库，后续 Codex、Claude Code、WorkBuddy 来源按文件字节游标读取增量，Gemini 在文件变化后恢复可见历史并按消息正文版本去重，Zcode 按数据库记录更新时间读取增量。每轮仍遍历目录并检查文件状态，未变化文件不读取内容；兼容格式识别按文件指纹及读取配置缓存，重启复用游标中的格式，修改字段配置后重新识别；针对工具日志和中间推理提供行级快速预过滤（无需 JSON 反序列化）；文件替换、截断或归档移动可能重读，通过消息标识去重，不会再次抽取成功处理的消息。
- JSONL 文件读取失败、内容无法入库或末尾超大半行连续失败两次后自动忽略同一份文件内容，失败次数写入数据库，重启后仍保留；文件替换、修改或追加后重新尝试。已越过的损坏、超大行仅计为跳过记录，详情显示忽略与跳过数量，不再列入待重试提示。数据库连接故障和模型抽取失败仍保留进度重试。
- 模型只处理启用来源的未抽取有效消息（新增及失败重试），积压消息每页最多读取 500 条，每批允许携带最多 6 条历史上下文；成功批次不可重新启动。消息入库与游标推进、抽取结果与成功标记分别通过事务保存，同一事项按 ID 更新。
- 会话组内严格按上下文依赖串行抽取，跨独立会话组支持有限并发（由 `WORKBENCH_SYNC_CONCURRENCY` 控制，默认 3），低推理档位，最长 180 秒；格式无效最多修复一次。同一数据库同时只运行一次同步。
- 通过头像设置调整同步间隔和启停，页面同步显示真实间隔；`SYNC_INTERVAL_MS` 与 `SYNC_ENABLED` 只作为首次启动默认值。
- 禅道采集分配给当前账号的激活 Bug、已解决待验证 Bug，以及未开始、进行中、暂停的任务；首次不导入历史已完成或已取消事项。待办编号可打开禅道原始页面；Bug 关闭后按关闭时间进入工作日志，本人解决并转交验证的 Bug 按解决时间进入日志，仍指派给本人的已解决 Bug 保留在待办中等待验证。Bug 状态由禅道驱动，界面不提供本地完成按钮；普通任务及后续综合归纳事项支持工作台手动完成与恢复。同步按禅道地址、账号、事项类型和编号去重，并补查移出个人列表的已采集事项，确认完成、转派或删除后才更新状态。旧版误归档或误删除的待处理事项会按详情恢复原编号；个人列表中缺少事项本身不会删除已有记录。连接失败、权限不足、缺页或详情补查失败时保留原有待办，其他渠道继续采集。禅道采集不调用模型。
- 会话来源内置采集 Codex、Claude Code、WorkBuddy、Zcode、Gemini CLI，自定义渠道可使用自动识别或通用 JSON / JSONL。

已有自动抽取事项可单独整理简介，日期、状态、来源证据与同步进度均保留。手工事项和手工修改过状态的事项跳过，原简介备份在 `.runtime/summary-titles-*.json`。整理时占用同步锁，避免与抽取重叠：

```bash
docker compose stop workbench
docker compose run --rm --no-deps workbench node dist-server/server/summarize.js
docker compose up -d workbench
# 本机开发环境也可运行 npm run tasks:summarize
```

## MCP 工作助手接入

工作台提供本机 Streamable HTTP MCP 接口，支持 Codex、Zcode 查询工作摘要、待办、脱敏证据、报告和禅道管理风险，并按权限创建或更新本地待办、保存助手撰写的报告。进入头像设置 → **MCP 接入**，启用服务并为每个客户端创建独立令牌；默认关闭，个人事项始终排除。

完整配置、14个工具、报告保存流程、权限及升级步骤见 [工作台 MCP 接入说明](docs/工作台MCP接入.md)。自动报告保留助手编辑内容，版本冲突不会覆盖现有记录；MCP 读取不触发模型或同步。

## 接口

| 接口 | 行为 |
|---|---|
| `GET /api/health` | 数据库就绪检查 |
| `GET /api/workbench` | 当日日志与手工、禅道待办摘要、当日日报、日期索引、数据版本、执行状态及来源状态；不携带证据正文 |
| `GET /api/records` | 按 `startDate`、`endDate`、`onlyRecords` 读取日历日志；`limit` 最多 100、`offset` 分页，返回总数及摘要 |
| `GET /api/tasks/:id/evidence` | 按需读取来源引用及失效原因 |
| `GET /api/settings` | 读取模型、采集源和同步设置，采集目录返回本机路径，密钥仅返回是否已配置；无法识别本机路径时通过 `unresolvedPaths` 标记 |
| `PUT /api/settings` | 按版本原子保存设置，留空密钥保留原值，过期版本返回 409 |
| `POST /api/settings/scan` | 输入读取方式及可选草稿 `paths`，扫描常用、草稿及已配置目录，返回本机路径 |
| `POST /api/settings/check-paths` | 输入记录格式和路径数组，核对本机与容器映射、访问权限及会话文件数量，不保存草稿 |
| `POST /api/settings/preview-records` | 输入 `auto` / `generic`、本机 `paths` 及可选 `mapping`，返回格式、检查数量、脱敏消息预览和问题，不调用模型或保存草稿 |
| `POST /api/settings/test-model` | 使用草稿基础地址、模型名称与输入或已保存的密钥测试连接，不保存草稿 |
| `POST /api/settings/test-zentao` | 输入草稿禅道地址、账号、密码或复用同一身份的已保存密码，检查 V2 登录及个人工作列表，返回待处理 Bug 和任务数；不保存草稿 |
| `GET /api/channel-logos/:id` | 读取已上传的渠道 Logo，按图片版本缓存；首页轮询只传图片地址 |
| `GET /api/daily-reports/:day` | 读取已保存日报；尚未生成时返回 `null` |
| `GET /api/daily-reports/:day/status` | 获取该日完整记录数及待整理数，不受历史分页影响 |
| `GET /api/periodic-reports/:type/:key` | 读取数据库周月报，尚未保存时返回 `null`；类型为 `weekly` / `monthly`，周期为 `2026-W40` / `2026-10` |
| `GET /api/periodic-reports/:type/:key/material` | 读取周期内已保存日报及原版聚合所需事项素材 |
| `POST /api/periodic-reports/:type/:key` | 输入 `{ "revision": 0 }` 生成或重新整理；过期版本返回 409 |
| `PUT /api/periodic-reports/:type/:key` | 输入 `{ "markdown": "报告正文", "revision": 1 }` 保存编辑；过期版本返回 409 |
| `GET /api/report-jobs` | 最近 30 次自动报告执行记录及结果 |
| `POST /api/report-jobs/:id/retry` | 重新安排失败或跳过的报告任务；运行中或已成功返回 409 |
| `POST /api/daily-reports` | 输入 `{ "day": "2026-10-01" }`，已有日报直接返回；输入 `"mode": "append"` 时仅整理新增或更新日志，并保存合并后的日报及整理标记 |
| `POST /api/tasks` | 创建手工事项，输入 `{ "title": "事项" }` |
| `PATCH /api/tasks/:id/pin` | 保存待办置顶状态，参数 `isPinned` 为布尔值；仅支持未完成的禅道和自定义待办 |
| `DELETE /api/tasks/:id` | 删除手动新增且未完成的待办；保留删除标记，避免旧缓存重复导入后恢复 |
| `PATCH /api/tasks/:id` | 修改手工或禅道任务状态，输入 `{ "completed": true }` 或 `false`；自动工作记录返回 409 |
| `POST /api/tasks/import` | 批量幂等导入旧手工记录 |
| `POST /api/sync` | 启动后台同步；可输入 `{ "source": "zentao" }` 仅同步禅道；运行中返回同一执行记录 |
| `GET /api/sync/:id` | 获取执行进度及结果 |

写接口接收 JSON；日期为 ISO 格式，日报按北京时间归档。服务连接失败时保留页面已加载记录，新增失败保留输入，恢复后可重试。

手动待办卡片提供删除按钮，请求失败时保留原记录。核心下方的采集渠道使用固定高度的单排 Logo、短名称和状态点，最多显示五个入口；当前六个渠道中的 Zcode 和 Gemini 收进“更多 +2”，点击即可查看渠道详情；超过五个时前四个保留，第五个以“更多 +N”收纳其余渠道，不再增加卡片行数。绿色表示已接入、橙色表示正在采集、灰色表示待接入或等待扫描、琥珀色表示对应来源存在读取提示。悬停可查看简要状态，点击 Logo、接入数量或同步状态打开详情弹窗，查看全部渠道、会话数量、最近同步结果和合并后的提示；弹窗支持关闭按钮、Esc 和遮罩关闭，并恢复入口焦点。

服务启动后会自动检查已配置会话目录的可读性，并从数据库恢复会话数量；关闭自动采集或仅同步禅道时，其他渠道也能显示已接入，无需重新扫描。连接检查只读取目录项和文件权限，不读取会话正文或调用模型。修改采集目录或读取方式后重新检查；缺失、未挂载或无法读取的目录显示对应提示，正常采集产生的错误仍保留。

顶部 Logo 和站点图标统一使用橙色工作收纳盒与勾选记录图标；“本机工作台”的绿色状态点表示服务已连接，连接中断时显示橙色“服务未连接”。

### Safari 与 Dock 图标

应用图标采用橙色底板、工作收纳盒与勾选记录，表达聚合工作记录和管理待办。由生图工具生成，正式高清图标为 `public/icons/workbench-1024.png`。页面提供 PNG 站点图标、Apple Touch 图标与网页应用清单，构建时一并发布。

升级后在 Safari 打开工作台，通过“文件 → 添加到 Dock”创建网页应用。如果已经添加到 Dock，可打开网页应用，在菜单栏选择“我的工作台 → 设置”，点击当前图标并选择 `public/icons/workbench-1024.png`，直接替换已有图标。

采集正文会在脱敏时移除数据库不支持的空字符，保留真实消息ID及其余文字，避免一条消息影响整批入库。模型抽取使用短消息和事项别名，保存前还原真实ID并严格验证来源；已有事项不提供当前批次无法引用的旧证据ID。失败提示只保存具体校验类别，不保存模型正文。

底部合并为紧凑同步栏，只显示最近同步时间与结果、必要的提示入口和“立即同步”按钮；新增、更新及读取消息数量在详情中完整保留，不再常驻“工作流就绪，等待下一次推进”等重复文案。渠道图标保存在本机，不依赖外部图片请求。

采集流向始终为「采集源 → 芯片」。同步返回实际新增或改变的记录后，按归属播放一次「芯片 → 待办」或「芯片 → 工作日志」：未完成的禅道任务进入待办，Codex、Claude Code、WorkBuddy、Zcode、Gemini CLI 的工作记录进入来源日期的日志。首次加载、无变化轮询和失败请求不播放分发流光，同批记录按目的地合并，后台停止播放。背景左右连线保留静态轨迹，不再随采集循环播放「待办 → 日志」；只有用户点击完成待办时才播放这条归档路径。

采集连线从单排渠道入口顶部的连接点出发，按入口顺序接入芯片底部的实际引脚。折线在芯片与渠道之间错开收拢，保持同序且不穿过 Logo；中等窗口的横向布局从渠道上方绕到芯片下方。“更多”入口共用一个连接点与引脚，隐藏渠道采集时同步高亮该入口及线路。空闲时绿色装饰流光每 16 秒走完一轮，工作时加快为 4 秒，当前渠道用橙色高亮并加快为 2 秒。空闲流光每秒更新 10 次、工作流光每秒更新 20 次，后台及减少动态效果模式停止播放，尺寸只在窗口或元素尺寸变化时重新测量。未接入渠道的装饰线路不代表真实采集。坐标以 SVG 自身视口测量，渠道组和状态区域尺寸变化时重新对齐。

芯片外圈使用 SVG 圆角方框。工作时橙色虚线与一段高亮光弧沿方框顺时针绕行，每 6 秒一圈、每秒更新 20 次；空闲时恢复静态绿色虚线，后台或减少动态效果模式停止动画。

## 验证

禅道测试经理待办的规则、字段配置、处理状态和接口详见[禅道测试管理说明](docs/禅道测试管理.md)。

```bash
npm test
npm run build
npm run test:harness
# 本机已有 postgres18 容器时，可直接运行隔离数据库测试：
npm run test:integration:local
```

普通测试不连接数据库或外部模型，包括设置持久化、密钥边界、并发保存、路径扫描、自定义渠道独立游标、停用重试和运行中配置快照。`test:harness` 启动真实 SDK 子进程与本地模型请求桩，验证设置指定的模型、地址与密钥、模型协议、低推理参数、无工具调用及凭证脱敏。

数据库集成测试使用临时隔离数据库，结束后自动删除。通过临时环境变量 `WORKBENCH_ADMIN_DATABASE_URL` 提供管理员连接，再运行：

```bash
npm run test:integration
```

也可提供名称包含 `_test` 的 `TEST_DATABASE_URL`，测试仅使用该测试库。覆盖任务持久化、旧缓存迁移、状态保护、事务回滚、失败重试及并发同步。测试不会启动浏览器。本机隔离入口通过容器内管理员创建随机测试数据库与专属角色，完成后清理，不读取业务数据库或管理员密码；可用 `WORKBENCH_TEST_POSTGRES_CONTAINER` 和 `WORKBENCH_TEST_POSTGRES_PORT` 指定测试 PostgreSQL 容器及本机端口。额外覆盖周月报真实持久化与并发冲突、来源编辑和撤回、过期模型保存保护、历史分页、自动任务租约及重试。

## 代码结构

- `server/`：接口、数据库迁移、记录适配、同步调度及 Harness 执行器、周月报存储及持久化自动报告任务。
- `shared/`：前后端数据类型。
- `src/`：工作台页面、待办、日报、周月报、日志日历、来源证据与归档动效。
- `scripts/`：Compose 初始化、启动及隔离数据库测试入口。
- `compose.yaml`、`Dockerfile`：多阶段镜像与本机 Compose 部署。

`.env`、`.runtime`、会话 SQLite 数据库及 WAL/SHM 文件、构建产物和日志均不进入 Git 或 Docker 构建上下文。代码备注、界面文案、日志和更新说明使用中文。
